# MAIL-126: **A mail folder in iCloud Drive, or in a folder another app syncs through File...

**Decision.** **A mail folder in iCloud Drive, or in a folder another app syncs through File Provider, is refused on the Mac until the shared iCloud Drive folder is built** (GKM-026). Picking one (Settings ▸ Storage ▸ Use Another Mail Folder…, or the first account's Choose…) says why and keeps the current folder: "That folder is in iCloud Drive. iCloud can remove files from this Mac to save space, or change them from another device while Mail is writing, and Mail can’t work with that safely yet…" (or, for Dropbox, Google Drive, OneDrive and the like, "That folder is synced by another app…"). A folder already chosen there is found at launch: the mail in it opens and can be read, but nothing of the sync starts (no download, no action replay, no attachments on demand, no server search), on every start path (`AccountSync.start`). The foot of the sidebar and the top of Settings ▸ Storage say "Your mail folder is in iCloud Drive, where Mail can’t write safely yet, so syncing with your provider is paused. The mail in the folder is untouched. Move the folder out of iCloud Drive in the Finder and choose it again in Settings ▸ Storage, or use the default mail folder."; each account says "Sync paused · mail folder is in iCloud Drive". Nothing is moved by the app. The check (`MailFolderPlacement.of`, injectable as `AccountServices.folderPlacement`) takes the path (`~/Library/Mobile Documents` is iCloud Drive, `~/Library/CloudStorage` is File Provider) and the folder's `isUbiquitousItem` (Desktop & Documents in iCloud; for a folder not made yet, the nearest one above it). Network volumes are not refused

**Why.** The store writes without `NSFileCoordinator` and reads originals that iCloud may have evicted to placeholders (iCloudDriveDesign.md, card F): reads fail or download unplanned, an index rebuild downloads the whole mailbox, and two devices can write the same files. Refusing is the smallest safe change until the coordinated design ships; moving the folder ourselves would be the migration that design owns (card D), so the person moves it. The path is checked as well as the resource value because an evicted or not yet indexed item may not report itself as ubiquitous, and File Provider folders are named for what they are. The sync is held rather than the store left closed so the mail already there stays readable. Still writing to a held folder: opening the store (its layout check, and recovery after a crash), drafts, imported messages and local edits such as spaces; GKM-104. A network volume has no eviction and no second writer the app can't see, so it stays allowed. `MailFolderPlacementTests` (the check on a real local folder and on iCloud Drive, File Provider and ubiquitous paths; picking refused with nothing remembered or written; the hold at launch and on a later start; a local folder starts as before). GKM-103
