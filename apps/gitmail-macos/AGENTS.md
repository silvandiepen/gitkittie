# GitKittie Mail

In development: the app shell (GKM-009), the mail store (GKM-005), the message list, threads, safe reader and local search (GKM-012, GKM-016), account setup (GKM-010) and sync (GKM-011) exist. Read docs/Features.md, Architecture.md, ThreatModel.md, ProviderAccess.md, Classification.md, Decisions.md, Roadmap.md and Plan.md (the work breakdown; each step is a GKM card on the GitKittie board). docs/ThreatModel.md lists the threats and which card owns each mitigation; read it before touching rendering, parsing, credentials, sync, the outbox or deletion. docs/ProviderAccess.md covers what Gmail, Microsoft and iCloud require. Follow root AGENTS.md and project-assets/Agents conventions. Native macOS first; shared UI-independent Swift services for later iOS/iPadOS. Apps depend on packages, never each other. Mail providers are authoritative for live mail; Git is optional, never silently uploads mail, and all future Git hosting operations go through GitPont. Security, privacy and correctness outrank convenience. Use synthetic fixtures; never commit real mail or credentials. No shipped feature is implied by this proposal.

## Build and test

- Generate: `npm run gitmail:generate` (XcodeGen; never hand-edit the `.xcodeproj`).
- App model tests (no app launch): `npm run gitmail:test`.
- Mail core: `cd swift/GitKittieMailKit && swift test`.
- `GitMail/Models` is UI-free and built into `GitMailTests` too; views live in `GitMail/Views`, the shared navy `Theme` comes from `swift/GitKittieUI`.
- `MailStore` reads mail with MailMIME (`MIMEMessageParser`); index schema 2 holds threads (MAIL-030), flags, folders and attachment text.
- Reader (GKM-012): `MailHTML` sanitizes, `MailReader` checks links and senders, `MailReaderWeb` is the locked-down web view (MAIL-032). Views in `GitMail/Views/{List,Reader,Search}`; list, thread and search state in `GitMail/Models/MailBrowser.swift`.
- `GitMailExtractor` is the sandboxed XPC service for attachment text (MAIL-031); `File ▸ Import Messages…` imports `.eml` into "On My Mac".
- Reader safety tests run real WKWebViews against a local listener: `swift test --filter WebViewSafetyTests`. Search benchmark: `GKM_BENCHMARK=1 swift test --filter SearchBenchmarkTests`.
- App icon: `GitMail/Assets.xcassets/AppIcon.appiconset`, rendered from project-assets `GitKittie/assets/icon_gitmail.svg`.
- Compose, drafts and the outbox (GKM-013, GKM-014): `MailCompose` (GitKittieMailKit) and `MailOutbox` (GitKittieMailProviders); in the app, `GitMail/Models/Sending` (UI-free, tested in `Tests/SendingTests.swift`) and `GitMail/Views/Compose`, `GitMail/Views/Outbox`. The outbox's guarantees are proven only by `OutboxIntegrationTests` against the real test server (`scripts/test-mail-server.sh start` in GitKittieMailProviders); run them after any change to sending. Accounts reach the outbox by registering `SendingAccountSettings` in `MailSending.registry` (GKM-010).
- Accounts and sync (GKM-010, GKM-011): `MailAccounts` (presets, verification, Keychain) and `MailSync` (the sync coordinator) in GitKittieMailProviders; sync state (folders, cursors, flags) in `sync.sqlite` via `MailStore+Sync.swift`. In the app, `GitMail/Models/AccountSync.swift`, `AppModel+Accounts.swift`, `AccountDraft.swift`, `MailFolderLocation.swift` (tested in `Tests/AccountTests.swift`) and `GitMail/Views/Accounts`. The account tests use the local test server when it runs (`GKM_TEST_MAIL_SERVER_DIR` is passed through by `scripts/test.sh`) and skip otherwise. Decisions MAIL-026..029.
- Everyday actions (GKM-015): the action journal in `MailStore+Actions.swift` / `RemoteMapping+Actions.swift` (sync.sqlite schema 4), replayed by `ActionReplayer` in MailSync; in the app `GitMail/Models/MailActions.swift` (planning, Undo) and `GitMail/Views/List/MessageActionCommands.swift`. Their guarantees are proven by `MailActionsIntegrationTests` against the real test server; run them after any change to actions or sync. Decisions MAIL-034..037.
