# GitKittie Mail

In development: the app shell (GKM-009), the mail store (GKM-005), the message list, threads, safe reader and local search (GKM-012, GKM-016), account setup (GKM-010) and sync (GKM-011) exist. Read docs/Features.md, Architecture.md, ThreatModel.md, ProviderAccess.md, Classification.md, Decisions.md, Roadmap.md and Plan.md (the work breakdown; each step is a GKM card on the GitKittie board). docs/ThreatModel.md lists the threats and which card owns each mitigation; read it before touching rendering, parsing, credentials, sync, the outbox or deletion. docs/ProviderAccess.md covers what Gmail, Microsoft and iCloud require. Follow root AGENTS.md and project-assets/Agents conventions. Native macOS first; shared UI-independent Swift services for later iOS/iPadOS. Apps depend on packages, never each other. Mail providers are authoritative for live mail; Git is optional, never silently uploads mail, and all future Git hosting operations go through GitPont. Security, privacy and correctness outrank convenience. Use synthetic fixtures; never commit real mail or credentials. No shipped feature is implied by this proposal.

## Build and test

- Generate: `npm run gitmail:generate` (XcodeGen; never hand-edit the `.xcodeproj`).
- App model tests (no app launch): `npm run gitmail:test`.
- Mail core: `cd swift/GitKittieMailKit && swift test`.
- iOS (GKM-025, MAIL-050..053): both Mail packages must also pass on the iOS Simulator — `xcodebuild -scheme GitKittieMailKit-Package -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' test` (and `GitKittieMailProviders-Package`; the integration tests reach the local test server from the simulator). The reader's WebKit tests run on iOS in the hosted test target `swift/GitKittieMailKit/TestHost` (`xcodegen generate`, scheme `MailKitHostedTests`); CI skips them in the unhosted package run. CI: `.github/workflows/swift-mail-ios.yml`. Keep platform code behind `#if os` only where APIs differ; iOS extracts attachment text in process (`InProcessTextExtractor`). See Architecture.md, "iOS and iPadOS".
- The app model is UI-free and lives in `swift/MailAppModel` (MAIL-067): the Mac app, the iPhone and iPad app (`apps/gitmail-ios`) and `GitMailTests` all compile it. Below, `GitMail/Models/…` means `swift/MailAppModel/…`. Views live in `GitMail/Views`, the shared navy `Theme` comes from `swift/GitKittieUI`. Keep the model free of AppKit and UIKit; a platform difference goes behind `#if os` there, and both apps must still build.
- `MailStore` reads mail with MailMIME (`MIMEMessageParser`); index schema 9 holds threads (MAIL-030), flags, folders, attachment text, List-Id, attachment names and sizes, space membership, verdicts (schema 4), the winning sender rule (schema 5), partial messages with their left-out parts (schema 6, GKM-036) the copy of provider deletions (schema 7, MAIL-075) and each account's Trash and Junk with the mark of mail only there (schema 8, MAIL-102: `MailIndex+TrashAndJunk.swift`; such mail leaves every view but its folder, and a new view query must go through `filterClause` or add `MailIndex.notTrashOrJunk`) and the From address index (schema 9, MAIL-098).
- Sil's answers to the Mail reviews (GKM-042): MAIL-073..080. Mail deleted at the provider is kept and marked, removed only by the account's "Remove mail deleted elsewhere" (`MailStore+ProviderDeletions.swift`, `RemoteMapping+Deletions.swift`, `SyncCoordinator.reviewDeletions`, and for mail without a Message-ID `DeletionProbe`, MAIL-104; sync.sqlite schema 5, and schema 7 for checks that could not tell, which go behind the others, MAIL-105); "Your name" is `MailAccount.senderName` (Account Settings… in the sidebar); unread receipts are in Focused (`MailIndex.categoryClause`).
- Reader (GKM-012): `MailHTML` sanitizes, `MailReader` checks links and senders, `MailReaderWeb` is the locked-down web view (MAIL-032). Views in `GitMail/Views/{List,Reader,Search}`; list, thread and search state in `GitMail/Models/MailBrowser.swift`.
- `GitMailExtractor` is the sandboxed XPC service for attachment text (MAIL-031); `File ▸ Import Messages…` imports `.eml` into "On My Mac".
- Reader safety tests run real WKWebViews against a local listener: `swift test --filter WebViewSafetyTests`. Search benchmark: `GKM_BENCHMARK=1 swift test --filter SearchBenchmarkTests`. Sync benchmark (first sync of 10,000+ messages against the test server; results and how to run in docs/Performance.md): `GKM_SYNC_BENCHMARK=1 swift test -c release -Xswiftc -enable-testing --filter SyncBenchmarkTests` in GitKittieMailProviders. The store's half alone, without a server (what grows per stored message, classification included): `GKM_STORE_BENCHMARK=1 swift test -c release -Xswiftc -enable-testing --filter StoreBenchmarkTests`. A query that runs for every arriving message must use an index; pin it in `IndexQueryPlanTests` (GKM-035, GKM-040).

- Accessibility (GKM-061, MAIL-089..091): every action has a menu item; `Views/MailboxCommands.swift` holds the Mailbox menu and `MailWindowRequests` (the sidebar's sheets, the search field, the filters), so a new sidebar or right-click action gets a Mailbox menu item too. Menu items with a keyboard shortcut have no `.disabled(…)` and capture no model state: SwiftUI syncs a menu item only at launch and when that menu is opened, so a shortcut would keep the launch state (GITKITTIE-098). They check `AppModel.canRun(_:)` (`swift/MailAppModel/AppModel+MenuCommands.swift`, tested in `Tests/MenuCommandTests.swift`) as they run; items without a shortcut may keep `.disabled`. For the same reason Send, Attach Files… and Delete Draft… don't use `@FocusedValue`: each compose window registers its `ComposeWindowCommands` in `ComposeWindows.directory` and the menu looks up the key window. Give a list row that uses `onTapGesture` an `accessibilityAction` and its menu's actions (`rowActions`). Informative text is `.secondary`, not `.tertiary` (2.4:1 on the navy). Increase Contrast (GKM-063, MAIL-112): every `Theme` colour has high-contrast values (`Theme.Swatch` in `swift/GitKittieUI/Theme.swift`); use the theme's colours, never a per-view stand-in, and keep `swift/GitKittieUITests/ThemeTests.swift` (in both Mail test bundles) passing when a value changes. The Mac UI is not driven by tests here; GKM-062 is the pass by hand.
- Low disk and where the window opens (GKM-090, GKM-067, MAIL-106..108): the free-space pause is the shared sync's (`AccountSync.downloadPause`, `DownloadPause.swift`; `AccountServices.freeSpace` / `minimumFreeBytes`: 2 GB on the Mac, the storage budget's minimum on iOS). Under it only the download coordinators stop; actions, attachments on demand and server search keep going, and the paused accounts start again by themselves. Start syncs through `AccountSync.start`, never around it, so a new start path can't download past the pause. The window's place is `LastPlace.swift` (device folder `preferences/last-place.json`), saved by `AppModel.rememberPlace()` on every selection and open-conversation change and restored in `AppModel.open()` (`MailBrowser.reopen`). Tested in `Tests/DownloadPauseTests.swift` (with the test server) and `Tests/LastPlaceTests.swift`.
- A mail folder in iCloud Drive or a File Provider folder (GKM-103, MAIL-126): refused when picked (`AppModel.mailFolderRefusal`, also checked in `useMailFolder`), and one already chosen holds the whole sync back at launch (`AccountSync.folderHold`, checked in both `start`s; `MailFolderHeldNotice` in the sidebar and Settings ▸ Storage). The check is `MailFolderPlacement.of` (path + `isUbiquitousItem`), injectable as `AccountServices.folderPlacement`; tests never touch the real iCloud Drive. It goes when the shared iCloud Drive folder (GKM-026, docs/iCloudDriveDesign.md on its branch) ships. Tested in `Tests/MailFolderPlacementTests.swift`.
- The sync's own floor and other stops on this device (GKM-091, MAIL-123, MAIL-124): `FreeSpaceFloor.swift` in MailStore (the floor and `LocalStoreProblem`), `SyncOptions.freeSpaceFloor` / `localStopRecheck`, the activities `.pausedForSpace` and `.cannotStore` in MailSync; the app passes `AccountServices.freeSpaceFloor` (the pause's own minimum: never add a second number) and words them in `SyncStatusText` / `LocalStopText`. A new writer of synced mail passes the floor to `storeSynced` / `storeSyncedPartials`. Proven by `LocalStopIntegrationTests` (GitKittieMailProviders, with the test server) and `Tests/DownloadPauseTests.swift`.
